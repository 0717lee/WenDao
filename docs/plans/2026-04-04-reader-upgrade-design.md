# WenDao 阅读核心升级设计

## 目标

围绕比赛答辩主链路，优先完成四项升级：

1. 清理知识图谱残留，避免项目定位继续围绕“图谱可视化”
2. 在阅读器内新增“AI 逐句精讲”
3. 增加章节目录导航，支持快速跳读
4. 为古籍库扩容建立稳定的数据与索引更新路径

本轮先按以下顺序实施：

`图谱清理 -> AI 逐句精讲 -> 目录树导航 -> 古籍库扩容`

## 设计原则

- 以现有阅读器为核心，不重做主界面
- 优先复用已有右侧学习面板区域，不引入新弹窗体系
- 句子切分依赖已有标点文，不引入古文 NLP 分句模型
- 先保证 Demo 效果和稳定性，再补搜索与扩容的第二层能力

## 方案决策

### 1. 知识图谱清理

不再保留“知识图谱”作为前台功能与项目卖点，但保留对阅读推荐仍有价值的“实体/阅读线索提取”能力。实现上做两件事：

- 删除或替换面向图谱的文案、依赖和测试残留
- 将后端内部依赖从“知识图谱节点”语义收敛为“阅读线索词表”，避免前后叙事冲突

这样可以保留已有推荐与线索提取能力，又不会让项目继续背着图谱包袱。

### 2. AI 逐句精讲

逐句精讲直接放进阅读器右侧面板，和“阅读笔记 / 学习卡片”并列，避免使用 Modal。用户点击句子后，右侧切换到“逐句精讲”面板，按步骤流式展示：

- 逐字解析
- 白话翻译
- 古注/出处参考
- 修辞与继续追问

后端通过 SSE 分步骤返回结果，前端边生成边显示，形成明显的“AI 在推理”的演示效果。

### 3. 章节目录导航

目录导航使用阅读器内的左侧抽屉，不再增加固定常驻列，避免桌面端布局过宽。目录数据直接复用文档已有的 `segments/chapter_titles`，点击后完成两件事：

- 设置阅读锚点并滚动定位
- 高亮当前选择章节

### 4. 古籍库扩容

扩容不直接手工堆静态文本，而是在现有 Kanripo 导入体系上扩展 `CURATED_WORKS` 与导入脚本。先保证默认内置古籍数量显著提升，再统一重建索引与预热推荐章节译文。

## 关键数据流

### 逐句精讲

1. 前端基于 `punctuatedText` 切句
2. 用户点击句子
3. 前端提交 `document_id + sentence + context + chapter_title`
4. 后端 SSE 依次返回各步骤结果
5. 前端右侧面板逐块渲染并支持“继续追问”

### 目录跳转

1. 文档详情接口返回 `segments`
2. 阅读器构建目录树
3. 用户点击章节
4. 设置锚点文本并滚动到对应位置

## 风险与校验点

### 风险

- 逐句精讲的 Prompt 结构不稳定，可能返回非结构化结果
- 原文列与标点列的句子切分需要保持对齐
- 目录导航不能破坏当前滚动同步体验
- 扩容后需同步更新索引和首页展示策略

### 校验点

- 阅读器中能稳定点击句子并打开精讲面板
- SSE 中断时前端能给出错误反馈
- 目录点击后能正确跳转到目标章节
- 图谱相关依赖不再出现在核心文档与前端依赖中
